-------------------------------------------------------------------------------------------------------------------------
第一部分：界面布局
-------------------------------------------------------------------------------------------------------------------------
目前分为两个网页风格： 经典色块、 简约档案

经典色块：为默认布局，面向于所有用户。通过大色块区分不同功能，引导清晰，对不同用户的适应性好。
简约档案：为备选布局，面向于老年用户。设计时需要确保字体大小清晰、留白多、层级靠编号和线条进行区分。

  · 选择面板里顺序固定：经典色块 → 简约档案
  · 界面布局只会影响主界面的布局，不同界面布局共用同一批数据和其他页面布局。
  · 其他页面在不同的界面布局下颜色风格会有所不同，需要参考设定的界面布局主题色。


-------------------------------------------------------------------------------------------------------------------------
第二部分：独立布局
-------------------------------------------------------------------------------------------------------------------------
  · 电脑端布局写在：css/skin-c.css（配 css/style.css 的变量）
  · 手机端布局写在：css/mobile.css
  · 手机端通过 <link media="(max-width: 600px)"> 单独加载，不靠 JS 判断

  ★ 铁律：当用户说明修改某一端时，不可修改另一个端的界面布局。两端的界面布局和交互逻辑不同，需要避免出现界面显示问题。如果用户没有说明修改的是哪一端，这需要根据用户截图判断，实在不确定不得自行修改，需要向用户确认。

第三部分：视口显示（等待修改）
-------------------------------------------------------------------------------------------------------------------------
  · 主容器使用：width: 100%; max-width: ...; margin: 0 auto;
  · 用 flex / grid 的比例分配空间（如 1 : 3 : 1），不要用固定 px 定容器宽
  · 高度跟视口算，不要用固定比例拍脑袋

  ★ 候选框（搜索预览框）的正确算法：
      起点 = 搜索框底边 + 10px
      终点 = 视口底部 − 24px 留白
      高度 = 终点 − 起点
    在 js/app.js 的 fitPanel() 里实算，CSS 不写死 height。

  ★★ 候选框必须用 position: fixed，不能用 absolute。
     原因：#top 为了「整页一屏」设了 overflow: hidden，
     绝对定位的面板只要超出 #top 底边就会被裁掉 ——
     算出来 525px，实际只能看见 90px，屏幕越矮裁得越狠。
     fixed 的基准是视口，谁也别想裁它。
     副作用：fixed 不跟随滚动。主页本来就不滚动，可以接受。

  ★ 踩过的坑：写 height: 58vh 是错的。
     58vh 是「屏幕高度的 58%」，和面板实际起点无关，
     标题区一变高它就溢出，变矮又留一大片空。必须用上面那条公式实算。

  ★ 只有「图标按钮、序号栏」这类本身就不该伸缩的东西，才允许固定 px。


  用户的屏幕是 1920×1080，但去掉任务栏（约 40px）+ 浏览器地址栏/书签栏（约 120px），
  网页实际能用的高度只有 **918px 左右**。

  所以：
    · **宽度基本不变**（1920）
    · **高度会少掉 150px 左右**

  布局要按这个前提设计：宽度方向不动，高度方向自动压缩。

  ★ 具体规则
      · 宽度：用 % / fr / max-width，不随视口高度变化
      · 高度：用 vh / flex / clamp，随视口高度压缩
      · 「填充剩余空间」的块（如三个入口）：flex: 1，自动上下缩
      · 字号、标题这种不能无限缩的：clamp(最小, 相对, 最大)
      · 任何方向上都不许写死整块的高度

  ★ 验证时用的视口尺寸：**1920 × 918**
    不要用自己随手设的窗口尺寸（如 1080×520）去论证布局对错，
    那个尺寸用户根本不会用，得出的结论没有意义。

  ★ 参考虚幻引擎 UMG 的容器思路（用户熟悉这套，沟通时可以直接对）
      Vertical Box           → display: flex; flex-direction: column
      Horizontal Box         → display: flex; flex-direction: row
      Slot: Fill（按比例分）   → flex: <n> 1 0
      Slot: Auto（按内容高）   → flex: 0 0 auto
      Size Box（最小尺寸）     → min-width / min-height
      Spacer（弹性空隙）       → gap / 空的 flex 子项
      Padding                → padding / margin
      Scale Box / DPI Scaling → clamp() + vh
      Anchors（锚点）          → position + inset，或者干脆用 flex 分栏

第四部分：文本显示
-------------------------------------------------------------------------------------------------------------------------
  · 所有 flex 子项加 min-width: 0（不加则不会小于内容宽）
  · 需要单行的：overflow: hidden + text-overflow: ellipsis + white-space: nowrap
  · 允许折行的：word-break: break-all + overflow-wrap: anywhere
  · 卡片容器统一加 flex-wrap: wrap
  · 顶栏允许横向滑动：overflow-x: auto（滚动条本身隐藏）


-------------------------------------------------------------------------------------------------------------------------
第五部分：描述文案
-------------------------------------------------------------------------------------------------------------------------
  · 网页的描述需要避免不够客观的描述，不可拿其他软件，网页，厂商等作为比较。
  · 当有新的界面添加，布局变化，功能更新等，这种需要添加或者修改描述的情况。需要向用户确认此描述的目标，以确保文案准确有效，不可自行添加。

第七部分：发布规则
--------------------------------------------------------------------------------
  ★ 默认状态：**只在本地生效**

    用户没有明确说「更新GitHub」时，不可上传任何内容至GitHub
      · 不 git commit
      · 不 git push

    本地更新完毕并验证后进行截图与汇报，然后等待用户的后续指令。

  ★ 用户明确说「更新 GitHub」时，严格执行下列要求：
  · 将网页顶栏 / 关于弹窗里那个日期需要修改为本轮修改的日期。
  · 把本文件夹内需要上传的内容上传至GitHub，上传时需要排除本地专属内容。
  · 本地专属内容为：
         PROJECT-REQUIREMENTS.txt / PITFALLS.txt / lab.* / layout-test/ / diag.html
  · 将本次上传的内容进行完整备份，只保留日期最新的备份。
