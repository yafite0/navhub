二、硬性规则（违反过的都吃过亏）
================================================================================

【两端隔离】
  · 用户只说改一端 → 另一个端的 CSS 一个字都不能动
  · 桌面只动 css/skin-c.css，手机只动 css/mobile.css
  · 分不清用户说的是哪端 → 看截图判断；判断不了就问，不许自己决定

【文案】
  · 不写「介绍页面布局」的话（左中右、就在这里、在那一列）
  · 不拿别的软件/网站/厂商做比较
  · 不解释原理、不辩解、不夸张
  · 不自己新增描述 —— 有新的界面/功能需要文案时，先问用户要表达什么

【布局】
  · 不写死整块高度，用 vh / flex / clamp
  · 填充链必须从根到叶子每一层都是 flex 容器，漏一层 flex:1 就是 0
  · 元素量出来 0×0，先查祖先的 display / overflow，别在优先级上打转

【配色】
  · 暗色下 `background: linear-gradient(...)` 光写 background-color 盖不住，
    要同时 background-image: none
  · 日间米白底黑字 → 夜间黑底米白字，整个反过来，不是只调深浅


================================================================================
三、改完之后（一条都不能省）
================================================================================

  1. 语法检查
     node --check 所有改过的 js 文件

  2. 冒烟（两端 × 五页）
     桌面 1920×919、手机 500×900
     检查：错误=无、横向溢出=否、关键元素数量对

  3. 截图
     改动涉及视觉的，必须截图确认，不能只靠探针数据

  4. 清理
     Remove-Item "tmp-*" -Force

  5. 汇报
     改了什么、为什么这么改、实测数字、还有什么没做
