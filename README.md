# 启航 · 精选网站导航

> **本网站由 DeepSeek 编写** —— 从页面结构、配色样式到收录哪些网站、每个站点怎么写介绍，
> 都是和 DeepSeek 边聊边改做出来的。

一个纯静态的网站导航页。零依赖、无需构建，双击 `index.html` 就能用，也可以直接托管到 GitHub Pages。

线上地址：<https://yafite0.github.io/navhub/>

**设计定位**：不是"什么网站都往里塞"的导航站，而是**只收录真正难找、值得收藏的官网**。
大众都知道入口的网站（B 站、淘宝之类）不占主页位置，但搜索时仍然能找到。

## 主页结构

- **顶栏**：站名 +「关于本站」+「赞助」两个入口；右侧是分类导航、最后更新时间、深浅色切换
- **天气条**：横跨整个版心的一条，位于内容区最顶部（顶栏之下、首屏之上），但它本身不吸顶
- **首屏**：左边是问候语、实时日期时钟、大搜索框、分类快捷词；**右上角是小工具按钮列**
  （单位汇率 / 字数Token / 二维码 / 翻译助手，按常用程度从上到下排）
- **常用直达**：只有被标记 `featured: true` 的网站才会显示这块；一个都没有时整块自动隐藏
- **精选分类**：按用途分组，每个分类是一张容器卡，里面是站点卡

小工具不再内嵌在主页里，统一收进 `tools.html` / `qr.html` / `translate.html` 三个页面，
主页右上角的按钮点进去即可。这样主页能专注于"找官网"这一件事。

`tools.html` 里的每个工具都是**独立界面**：靠地址栏上的 `?tool=unit` / `?tool=counter` 决定显示哪一个，
页面上没有工具切换栏。想加新工具，就再写一个 `<section class="tw-panel" data-tool-panel="xxx">`，
并在 `js/tools.js` 的 `TOOL_META` 里补一条标题和说明即可。

## 关于本站 / 赞助

顶栏左侧有两个入口，内容都在 `js/data.js` 的 `about` 字段里配置：

```js
about: {
  title: '关于本站',
  lead: '……',                              // 顶部那句引导语
  items: [{ t: '为什么做这个', d: '……' }],   // 介绍块，可增删
  tags: ['完全免费', '无广告', '不收集数据', '开源'],
  credit: '本网站由 DeepSeek 编写',          // 弹窗里的署名行，留空则整行隐藏
  github: '',                              // 填上仓库地址后按钮就会真的跳转
  sponsor: 'https://afdian.com/a/L1295598306',
  sponsorText: '请我喝杯奶茶',
  note: '……'
}
```

- `github` 留空时按钮显示「链接待补充」，点击会提示；填上地址后自动变成可跳转。
- 赞助按钮用的是爱发电图标（`assets/icons/afdian.png`），想换文案改 `sponsorText` 即可。

## 怎么添加网站

打开 `js/data.js`，往对应分类的 `sites` 数组里加一项：

```js
{
  name:  'Steam',                             // 显示名字
  url:   'https://store.steampowered.com/',   // 官方网址
  short: '游戏最全、打折最狠',                  // 卡片上的一句话
  key:   '蒸汽 游戏平台 买游戏',                // 搜索用的额外关键词
  icon:  'assets/icons/steam.png',            // 网站图标（放 assets/icons/ 下）
  shots: [                                    // 官网截图，2~3 张，放 assets/shots/ 下
    { src: 'assets/shots/steam-1.jpg', t: '商城首页' },
    { src: 'assets/shots/steam-2.jpg', t: '特惠打折页' }
  ],
  shotUpdated: '2026-10-06',                  // 截图更新日期，会显示在弹窗里
  intro: {
    tagline: '全球最大的 PC 游戏商城',           // 一句话定位
    pros:  ['优点 1', '优点 2'],                // 优点（数组）
    cons:  ['缺点 1', '缺点 2'],                // 缺点（数组）
    best:  '适合什么样的人用',                   // 推荐人群
    tips:  '使用小提示'                         // 可省略
  }
}
```

- 只填 `name / url / short` 也能用，卡片上的「介绍」按钮会自动隐藏。
- 加 `featured: true` 会额外出现在顶部「常用直达」。
- 新增分类：复制一整块 `{ id, name, icon, desc, sites }` 改内容。

### 大众网站放哪

`data.js` 一共分三档，加站点时先想清楚该放哪一档：

| 档位 | 字段 | 出现在哪里 | 有没有图标和介绍 |
|---|---|---|---|
| 1 · 精选 | `categories[].sites` | 主页 + 全部网站页 | 有截图、图标、优缺点 |
| 2 · 完整索引 | `index` | 全部网站页 + 搜索 | 有图标 + 一句话说明 |
| 3 · 仅网址 | `urls` | **只在搜索时出现** | 无图标、无介绍，只有名字和网址 |

分档标准是「搜索它的名字时，前排会不会被广告或山寨站占掉」：

- Steam、Xbox 商店、PS Store 这类，搜索前排常是加速器广告和下载站 → 进第 1、2 档；
- 百度网盘、淘宝、知乎这类，官网本来就排第一 → 进第 3 档，只留网址。

第 2、3 档都要写 `key`（语义关键词）。第 3 档尤其重要，它是搜索的唯一入口 ——
比如给网盘类都写上「网盘 云盘 存文件」，用户搜「网盘」时会一次带出
百度网盘、阿里云盘、夸克网盘、迅雷等全部候选。

`region` 字段区分国内 / 国外（`'cn'` / `'global'`），「全部网站」页会按它分组，
并给国外站点标注网络提示。
这些站点**不在主页展示**，但搜索名字依然能找到 —— 既不占主页位置，又不会让人搜不到。

## 卡片交互

卡片平时显示域名，鼠标移上去（或键盘 Tab 聚焦）会浮出两个按钮：

- **介绍** —— 打开弹窗，里面是官网首页截图 + 优点 / 缺点 / 适合谁 / 小提示

## 图标和截图

**图标**：统一放在 `assets/icons/`，**文件名就是域名（去掉 www）**，例如 `iqiyi.com.png`、`store.steampowered.com.png`。
页面会自动按域名去找这个文件，所以**不用在数据里写 `icon` 字段**；
只有域名和图标对不上的才需要显式指定（比如网易云音乐用的是 `163.com.png`、通义千问用的是 `qwen.png`）。

加载顺序：数据里的 `icon` → `assets/icons/<域名>.png` → 在线 favicon 服务 → 名字首字色块。
所以本地图标缺失也不会出现空白，最差也能看到名字首字。

三个踩过的坑，以后改这块注意：

1. **图标是异步加载的，必须直接画进最终要显示的那个元素**。
   早期写法是"先造一个临时元素、加载好再把内容搬过去"，结果搬过去的只有文字占位 ——
   因为 `onload` 回调把图片塞进了那个临时元素，而它根本没进 DOM。
   现在统一走 `paintIcon(box, site)`，卡片和弹窗都直接传目标元素。
2. **不要给这种图标加 `loading="lazy"`**。图片在 `onload` 之前是游离在 DOM 外的，
   浏览器没法判断它"在不在视口里"，懒加载可能永远不触发，图标就一直卡在名字首字。
   同理也别加"几秒后强制变回首字"的超时兜底 —— 它会把已经加载好的状态覆盖掉。
   图标只有几十 KB，直接加载即可。
3. **图标尽量找 48px 以上的**，容器是 42×42，拿 16×16 的放大后会糊。可用的来源：
   `favicon.im/<域名>?larger=true`（常能拿到 128 / 256）、`icons.bitwarden.net/<域名>/icon.png`（64 上下）。
   个别站点两个源都只给小图（Unity 48、itch 32），够用即可。

**截图**：弹窗顶部放的是**未登录状态下的官网截图**（每个站点 2~3 张），文件放在 `assets/shots/`。

- **整个截图区都可以点**，点哪一块都能打开全屏；弹窗内两侧的箭头用来翻页（只有一张图时自动隐藏），
  全屏里也可以直接用左右方向键；
- 右下角显示「2 / 3 · 特惠打折页」这样的页码；
- 左上角会标明"官网截图 · 未登录状态 · 更新于 YYYY-MM-DD"，日期取自该站点的 `shotUpdated` 字段，
  内容换新图后记得同步改一下，免得访客看到过期的信息。

弹窗整体尺寸是 `min(1120px, 95vw) × 92vh`，**不出现滚动条**：截图区高度用 `clamp(158px, 26vh, 300px)`
跟着视口伸缩，内容区自适应。所以写 `pros` / `cons` 时建议每侧控制在 4 条以内、每条 25 字上下，
太长的文案在小屏上会被挤。

全屏查看用的是**固定画框**（1180×664，`object-fit: contain`），所以不管原图多高多宽，
显示出来的尺寸都是一样的，不会忽大忽小。

**关于截图文件本身**，有几条经验（踩过的坑）：

- 宽统一 `1200px`，高度按原比例，**不要强行拉伸或裁成同一个比例**；
- 抓完一定要**把底部的纯色空区裁掉** —— 很多站点（Steam、TapTap）首屏内容是懒加载的，
  截图工具不会滚动页面，下方会留一大片死黑，看起来像图坏了；
- **每张图内容要不一样**：同一个榜单页换个路径往往还是同一个页面（TapTap 的 `/top/download`
  和 `/top/rated` 就是同一个），换之前先确认；
- 记得避开 404 页：有些站点会返回 HTTP 200 但内容是"找不到页面"（TapTap 的 `/news` 就是），
  文件大小会明显偏小（100 多 KB vs 正常 700KB+），对比一下就能看出来。
可以用在线截图服务生成，例如：

```
https://image.thum.io/get/width/1440/https://example.com/
```

拿到图后裁掉顶部约 880px 高度、缩到 1200px 宽、存成 JPG（约 100KB 一张最合适）。
个别站点（如 Epic）开了 Cloudflare 人机验证，部分截图服务会被拦，换一个服务或自己截图即可。

## 发布到 GitHub Pages

1. 在 GitHub 上新建一个公开仓库。
2. 把本目录下所有文件推上去：

   ```bash
   git init
   git add .
   git commit -m "init: 导航页"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```

3. 打开仓库 **Settings → Pages**，Source 选 **Deploy from a branch**，
   Branch 选 **main**、目录选 **/ (root)**，保存。
4. 约 1 分钟后访问 `https://<你的用户名>.github.io/<仓库名>/`。
   以后每次 `git push` 都会自动重新发布。

## 二维码生成（独立页面）

`qr.html` 是一个独立的二维码工具页，从主页小工具区的入口条进入。做成独立页面是因为它比其它小工具重
（实时预览 + 外观设置 + 导出），塞进主页面会把小工具区拉得很长。

- **纯本地生成**：用开源库 `qrcode-generator`（MIT 协议，作者 Kazuhiko Arase）在浏览器里现场绘制，
  生成过程**不发起任何网络请求**，内容不会离开用户的电脑，断网也能用
- 实时预览、尺寸调节、纠错等级（L / M / Q / H）、前景与背景配色
- 导出 PNG（1024×1024，适合打印）、导出 SVG（矢量图），以及复制图片到剪贴板
- 支持带参数进入：`qr.html?u=https://example.com` 会自动把内容填好
- 页面上有一块「关于这个工具」，写明了技术来源、安全性、使用注意和纠错等级怎么选

## 翻译助手（独立页面）

`translate.html` 是另一个独立页面，从主页小工具区的入口进入。做法是「带你去」而不是「替你翻」——
纯静态页面里直接调翻译接口，要么需要 key（前端 key 等于公开，会被盗刷），要么依赖随时会失效的通道。

页面**左右分栏**：左边是很窄的「网页在线翻译」竖列表，右边整块留给「AI 网页翻译」（它内容最多）。
窄屏（< 980px）自动改成上下堆叠。

**路线一：网页在线翻译**

只收录提供网页版翻译的站点，点一下直接在新标签打开：百度翻译、有道翻译、必应翻译、腾讯翻译君、
搜狗翻译、彩云小译、Google 翻译、DeepL。不提供网页翻译的软件不会出现在列表里。

**路线二：AI 网页翻译**

一共三条提示词，配合使用：

| 提示词 | 什么时候发 |
| --- | --- |
| 双向翻译规则 | **新会话开始时发一次**，AI 回复「确认」就生效，不用重复发；它定义了翻译方向和回译规则 |
| 更换翻译语言 | 已经约定好规则之后，想换语言时发 |
| 更换语气风格 | 想换语气时发 |

选好「语言A（对方语言）/ 语言B（我的语言）/ 语气风格」后，当前提示词的对应位置会自动更新；
提示词可以直接编辑微调，**换语言时只会改动那几处，你手写的内容会保留**。
语气风格只有两个选项：自然口语（默认）、严肃书面。

点下面的 AI 按钮会**先把当前提示词复制到剪贴板，再打开该 AI 的对话页**，过去直接粘贴即可。
列表只收录能网页对话的 AI（DeepSeek、豆包、Kimi、通义千问、腾讯元宝、文心一言、
智谱清言、讯飞星火、ChatGPT、Claude、Gemini）。

**三个细节**：

1. 改「语言」下拉框会自动跳到「更换翻译语言」，改「语气风格」会自动跳到「更换语气风格」——
   这两个动作本身就意味着"我要换"，所以直接把对应的提示词递给你；「双向翻译规则」不参与自动跳转。
2. **但这个跳转只在复制过提示词之后才发生**。刚打开页面、还没复制过时，切换语言只会刷新当前这条
   「双向翻译规则」的内容，不会跳走 —— 因为那时候用户还在设定初始语言。
   点「复制这条提示词」或点任何一个 AI 按钮，都算"已复制"。
3. 两种语言选成一样时（比如语言A 和语言B 都是中文），复制按钮会变灰、右侧 AI 按钮也会禁用，
   并弹出红色警告提醒确认翻译目标 —— 因为没有翻译方向，复制了也没用。

提示词本体在 `js/translate.js` 的 `PROMPTS` 数组里，每条有 `name / tag / tip / build` 四个字段，
想改文案或者加一条新的，直接改那里就行。

**复制提示**

复制成功或失败都会在屏幕中下方弹一个胶囊提示，2.4 秒自动消失、**不拦截点击**
（`.toast` 设了 `pointer-events: none`），不需要手动关闭，也不会挡住下面的按钮。

### 最后更新时间

顶栏右侧会显示「最后更新 2026-10-06 19:00（2 小时前）」，时间来自 `js/data.js` 的 `lastUpdated` 字段：

```js
lastUpdated: '2026-10-06 19:00',
```

- 格式 `YYYY-MM-DD HH:MM`，精确到分钟，**是静态值，内容更新后需要手动改这里**；
- 括号里的相对时间（分钟 / 小时 / 天 / 周 / 月 / 年）由页面自动计算，每分钟刷新一次，不用管；
- 留空或格式不对时，这个徽章不会显示。

### 关于 Token 和价格

**Token 数是估算值，不是官方分词结果。** 实现方式是按字符类型（汉字 / 拉丁字母 / 数字 / 标点）
分别乘以各模型的经验系数，通常误差在 15% 以内，适合用来估用量和花费，不适合当成计费依据。
内置了 DeepSeek、通义、GLM、GPT、Claude 和通用中英混合六组系数，可在下拉里切换。

**价格需要手动填。** 纯静态页面没法可靠地抓取官网价格（跨域会被 CORS 拦，官网一改版解析就失效），
所以做成了手动填价：默认填入一组 DeepSeek 参考价；切换模型时，下方「核对 XX 官方价格」的链接
会自动指向该厂商的官方定价页，**请以官网最新价格为准**。
非 DeepSeek 模型没有内置参考价，需要自己到官网查完手动填写。

费用按这类模型的通用计费方式计算：

```
未命中输入费用 = (输入 token - 缓存命中 token) / 100万 × 输入价
缓存命中费用   = 缓存命中 token / 100万 × 缓存命中价
输出费用       = 输出 token / 100万 × 输出价
```

「输入 token」会随文本框内容自动更新，手动改过之后就固定住不再自动覆盖（清空则恢复自动）。

## 实现上的两个注意点

1. **`hidden` 属性必须真正生效**。样式表里加了一条 `[hidden] { display: none !important; }`。
   否则像弹窗遮罩这种写了 `display: flex` 的元素，即使带 `hidden` 也会铺满全屏，
   变成一个看不见的全屏遮罩，把整页的点击和滚轮全部吃掉。

2. **弹窗没有"中间状态"**。弹窗的显示完全由 `hidden` 属性控制，内容和遮罩都不依赖 JS 附加的类，
   遮罩也不做透明动画。这样可以确保不会出现"滚动被锁住、但弹窗还没变可见"的情况。

3. **改了 css / js 记得改版本号**。`index.html` 引用样式和脚本时带了 `?v=...`，
   修改后把版本号改一下（例如 `?v=20261006c`），否则浏览器可能继续用缓存里的旧文件。

## 技术说明

**零依赖**：整站没有引用任何一个 npm 包，没有构建步骤，没有框架。
所有页面都是手写的 HTML / CSS / 原生 JavaScript，打开 `index.html` 就能跑，
也可以直接扔到任何静态托管上。

**为什么不用框架**：这个站点一共 5 个页面，引入框架反而要多一层打包工具和依赖树，
部署前还得先构建。用原生写法改起来直接，部署就是把文件拷过去。

**浏览器兼容**：面向现代浏览器（Chrome / Edge / Firefox / Safari 最近两年内的版本）。
用到的几个较新特性都做了降级，拿到旧浏览器上最差也只是少显示一项信息：

| 特性 | 用在哪 | 不支持时的表现 |
|---|---|---|
| `:has()` | 配置检测页收起重复标题 | 只是多显示一块标题，功能不受影响 |
| `navigator.deviceMemory` | 读内存大小 | 显示「浏览器未提供」 |
| `navigator.userAgentData` | 读系统版本 | 退回解析 UA 字符串 |
| `navigator.clipboard` | 各处的复制按钮 | 退回 `document.execCommand('copy')` |
| `WebGL` + `WEBGL_debug_renderer_info` | 读显卡型号 | 显示「读不到显卡信息」 |

**响应式断点**：

| 断点 | 变化 |
|---|---|
| `≤ 1060px` | 精选卡片从多列减到两列 |
| `≤ 900px` | 配置检测页由左右两栏改为上下排列 |
| `≤ 720px` | 顶栏按钮收成图标，卡片操作按钮常驻 |
| `≤ 620px` | 小工具入口纵向堆叠 |
