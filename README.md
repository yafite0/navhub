# 启航 · 精选网站导航

这是一个纯静态的网站导航站。收录的精选的官网入口，另附少量实用工具（单位换算、二维码、提示词预设等）。无任何打开构建步骤，依赖与后端，安全可靠，打开“index.html”文件即可运行。

## 一、它长什么样

两套界面，用户自己选：

| 界面 | 面向 | 特点 |
|---|---|---|
| **经典色块** | 所有用户（默认） | 品牌蓝 + 彩色大卡片，信息密度高 |
| **简约档案** | 老年用户、喜欢安静阅读的人 | 米白纸面、编号、细线、大字号、留白多 |

**关键设计**：界面布局只影响**主界面**。其他页面（其他网页、工具、提示词、二维码）在两套界面下共用同一套布局，只是配色跟着主题走。

两端（电脑 / 手机）是**两套完全独立的布局文件**，不是同一套代码靠媒体查询伸缩。

## 二、五个页面

| 文件 | 用途 |
|---|---|
| `index.html` | 主页：搜索、收藏栏、三个入口（预设 / 官网 / 工具）、天气 |
| `sites.html` | 其他网页：100 个站点，分类树 + 标签筛选 |
| `tools.html` | 工具：单位换算、字数统计、驱动查询、桌面快捷方式 |
| `translate.html` | 提示词：选场景 → 拿到写好的提示词 → 复制给 AI |
| `qr.html` | 二维码生成 |

## 三、技术栈

```
HTML        原生，无框架
CSS         原生，CSS 变量做主题
JavaScript  原生 ES5 风格，无打包
存储        localStorage（收藏、皮肤、城市）
部署        静态托管即可（GitHub Pages）
```

**为什么不用框架**：打开就要快。这个站点的主要动作是「点一下就走」，没有状态要管，引入框架反而增加首屏负担和构建复杂度。

**为什么 JS 写成 ES5 风格**：不经过编译，直接跑在浏览器里。`var` + `function` 是为了让任何浏览器都能读，也方便不熟悉现代工具链的人改。

## 六、我要改造它 —— 从哪下手

### 加一个站点

只改 `js/data.js`。找到对应的小类，往 `sites` 数组里加一项：

```js
{
  name: '示例站',
  url: 'https://example.com/',
  short: '一句话说明它是干什么的',   // 卡片上显示
  key: '关键词 用空格隔开',          // 搜索用
  region: 'cn'                       // cn = 国内，不写 = 国外
}
```

如果想让它在**标签筛选**里出现，还要在 `js/tags.js` 的 `map` 里补一条：

```js
'示例站': ['网页版', '免费', '国内']
```

> 不加也能搜到，只是标签筛选里筛不出来。

### 加一个分类

同样在 `js/data.js`：小类往 `categories` 加一项，并写上 `group` 指到大类。

```js
{
  id: 'my-cat',              // 稳定标识，不要随便改（链接会断）
  group: 'software',         // 属于哪个大类
  name: '我的分类',
  icon: '📦',
  desc: '这个分类放什么',
  sites: [ /* ... */ ]
}
```

### 换配色

颜色全部是 CSS 变量，定义在 `css/style.css` 顶部：

```css
:root {
  --bg: #F4F3EF;
  --surface: #FFFFFF;
  --text: #14161A;
  --border: rgba(0,0,0,.08);
  /* ... */
}
```

改这十几个变量，整个站点的配色就变了。**不要逐条改具体元素的颜色**，那样维护不住。

### 改布局

**先读 `css/skin-c.css` 或 `css/mobile.css` 的注释。** 两个文件开头都写清楚了「这一块是什么结构、为什么这么排」。

三个必须知道的前提：

1. **两端隔离**
   桌面规则只在 `skin-c.css`，手机规则只在 `mobile.css`。
   `mobile.css` 通过 `<link media="(max-width: 600px)">` 条件加载，**里面不写 `@media`**。
   改桌面时不要碰 `mobile.css`，反之亦然。

2. **选择器要带主题前缀**
   `skin-c.css` 里的选择器都长这样：`html[data-theme="c"] .xxx`（特异性 0,2,1）。
   裸写 `.xxx`（0,1,0）**压不住它**，必须加同样的前缀。

3. **填充链不能断**
   从根到叶子，每一层都得是「有高度的 flex 容器」，`flex: 1` 才有效。
   少一环，下面全部算成 0。

### 加一个新页面

复制 `qr.html` 当模板（它是最短的完整页面），然后：

1. 建 `css/你的页面.css` 和 `js/你的页面.js`
2. 在 HTML 里引入 `style.css` + `skin-c.css` + `mobile.css` + 自己的 css
3. 引入 `data.js` + `topbar.js`（顶栏必须一致）
4. 在导航里加上入口

> 顶栏在所有页面**必须完全一致**，不要因为页面不同而改它的按钮。

## 七、几个设计决定，以及为什么

**搜索框为什么能直接跳网址**

输入 `baidu.com` 会先去探测这个域名通不通，通了就直接跳，不通才交给搜索引擎。输入中文直接搜索。

判断链：

```
含中文              → 搜索引擎
已带 http(s)://     → 直接打开
含点号              → 补 https:// 探测
单个英文词          → 补 .com 探测
都不通              → 搜索引擎
```

**为什么只有简约档案做了严格的响应式**

经典色块是原版布局，视觉上靠大色块撑开，小范围变形不明显；简约档案字大留白多，比例一错就很刺眼。所以后者做了逐层的容器化处理。

**候选框为什么用 `position: fixed`**

主页的 `#top` 设了 `overflow: hidden` 来保证「整页一屏」。绝对定位的候选框只要超出 `#top` 底边就会被裁掉 —— 屏幕越矮裁得越狠。`fixed` 的定位基准是视口，绕开了这个限制。

代价是：`fixed` 不跟随页面滚动。主页本来就不滚动，可以接受。

## 八、给接手的 AI agent

如果你是被派来改这个项目的 agent，**按这个顺序读**：

```
1. README.md（本文件）           ← 先搞清这是什么
2. `docs/` 里这五份，按顺序读：
     docs/PROJECT-REQUIREMENTS.txt   需求规范（最高优先级）
     docs/EXECUTION-GUIDE.txt        开工和收尾流程
     docs/SITE-STRUCTURE.txt         完整 DOM 树和文件分工
     docs/PITFALLS.txt               已经踩过的坑
     docs/TODO.txt                   当前待办
3. css/skin-c.css 或 mobile.css 的文件头注释
```

**几条最容易犯的错，先说在前面**：

- 只改一端时，另一端的 CSS 一个字都别动
- 不写「左边选、右边看」这类介绍页面布局的话，用户看一眼就知道
- 不拿别的软件做比较，不解释原理
- 元素量出来 `0×0`，先查祖先的 `display`，不要在样式优先级上反复试
- 改完必须跑：桌面 1920×919 + 手机 500×900，五个页面都看一遍
